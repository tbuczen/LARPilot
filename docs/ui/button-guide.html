Button system

One meaning per color, one size per context. Applies to every <button> and every <a class="btn"> in Twig templates and Stimulus controllers. Built on the Bootstrap 5.3 classes already in use, so templates only change class names, never markup structure.

1. Roles: what each color means

Pick the class by what the action does, never by what looks nice next to its neighbours.

Create
Create — btn-success + bi-plus-lgBrings a new thing into existence: Create character, Add faction, New quest, Invite participant, Add booking.
Save
Primary — btn-primary + bi-check-lgCommits the current form or the main step: Save, Submit application, Apply filter, Accept, Confirm (non-destructive), Import.
Edit
Edit — btn-outline-primary + bi-pencilOpens something for changing: Edit, Modify, Manage, Decision tree, Settings.
View
Info — btn-outline-info + bi-eye / bi-info-circleRead-only look: View, Details, Preview, Character sheet, Version history, Help. Text color darkened from Bootstrap cyan so it passes contrast on white.
Unpublish
Alert — btn-warning + bi-exclamation-triangleSignificant but reversible: Archive, Unpublish, Suspend user, Reset matching, Revoke invitation, Cancel LARP (workflow).
DeleteDelete
Delete — btn-outline-danger to open the confirm modal, btn-danger for the final confirmDestroys or rejects: Delete, Remove, Reject application, Ban. Destructive actions always go through a confirmation; the solid red appears only at the point of no return.
BackCancel
Neutral — btn-outline-secondaryLeaves without changing anything: Back (bi-arrow-left), Cancel, Close, Clear filters, secondary tools (Copy, Fit image, Export).

2. Sizes: decided by the group, not the button

Every button in one group shares one size. Spacing comes from the wrapper's gap, never from me-*/ms-* on buttons.

5. Rules

  • Do use <a class="btn …"> for navigation (GET) and <button type="…" class="btn …"> for submits and JS actions. Both take the same classes.
  • Do keep at most one solid button per group. Everything else in the group is outline.
  • Do order groups neutral → info/edit → alert → destructive → primary/create, with the primary action last (rightmost).
  • Do use the ui.* macros in templates/macros/ui_components.html.twig where one fits.
  • Don't use btn-secondary (solid grey), btn-info (solid cyan), btn-dark, or btn-link for actions. Plain text links stay plain <a> without btn.
  • Don't use btn-light / btn-outline-light except on dark or colored surfaces (photo headers, cookie banner).
  • Don't add hover lifts, gradients or shadows per page. Hover only darkens the fill (solid) or tints the background (outline).
  • Don't put me-1/me-2 on icons inside buttons; the button's flex gap spaces them.
  • Allowed exceptions: decision tree toolbar (node-type colors as a legend), thumbs up/down vote toggles, SSO and social brand buttons, btn-lg groups on mobile staff pages.
